Previous review fixes: #2 (exitCode), #4 (DA filter after attach), #5 (seed only new ws) OK. #1 only partially fixed (see 5). #3 fixed but with a new problem (see 2).

1. daemon/internal/api/cmds.go:322 - preset.new/preset.rm write presets.json + s.presets but the UI is never told; renderer keeps its startup list (src/App.tsx:105), so the new preset is missing from the Agentes tab, and the next save in AgentsMenu (src/components/AgentsMenu.tsx:95/168, sends stale `mine`) wipes the CLI-created preset (or brings back the removed one). Also ui.go:190 presets.get does LoadPresets outside s.mu and can overwrite s.presets with a list older than a parallel CLI preset.new - fix: after preset.new/rm `s.emit({type:"presets", list})` and have the renderer `set({presets})`; in presets.get, load+assign under one lock (or re-read after store save).
2. cli/colmeia.mjs:230 - `windowsVerbatimArguments: true` is also set on the non-.cmd branch: libuv then skips quoting argv[0], so an .exe under a path with spaces (e.g. `C:\Users\John Smith\AppData\Local\Programs\Ollama\ollama.exe list`) gets argv split, `ollama` sees `Smith\...` as the subcommand, run() returns '' silently - fix: set windowsVerbatimArguments only in the cmd.exe branch (`{ ..., windowsVerbatimArguments: command !== file }`).
3. daemon/internal/api/cmds.go:426 - `--model` override lives only in this one buildSpawn call; card persisted as {id,preset,title,cwd}. ui.go:122 restart and app-reopen Ensure (opencode has restartOnReopen=true) rebuild from the preset → card silently comes back on the preset's default model (opencode session also resumes under another model) - fix: store `model` in the card Args/workspace and in spawnIn from the UI (or keep it in term Info and reuse it in RestartWith/Ensure).
4. daemon/internal/api/cmds.go:393 - spawn by title takes the first EqualFold label match with no ambiguity check; the Agentes menu allows duplicate labels (ids are `agent-<ts>`), so `colmeia spawn Apis-A` may launch the wrong preset/model silently - fix: collect all label matches; >1 → error "preset ambíguo: Apis-A (id1, id2)" like resolveCard does.
5. daemon/internal/api/wait.go:75 - "only lines since previous prompt" works only for PowerShell: a bash/zsh prompt with the typed command (`user@h:~/x$ make`) matches neither promptRe (needs end-of-line) nor psPromptRe, so the scan runs through older commands' output in the 20-line tail → stale `error:` makes a clean run "error" - fix: add a prompt-with-command regex (e.g. `^\S+[$%#>]\s+\S`, or the same text as the final prompt line used as prefix) to the break condition.
