## 4. Rust/Tauri port notes
Easy:
- links.ts (HashSet), historyStore, store.ts (serde_json + tempfile persist), notesStore, usage.ts (rusqlite read-only, `notify` crate replaces fs.watch), tmux.ts (std::process::Command; async w/ tokio), apiServer (tokio UnixListener, line-delimited JSON, same wire protocol → CLI .mjs unchanged), types.ts → serde structs.
- CLI stays Node or becomes a small Rust bin (compact()/printResult regex port trivial).
Medium:
- ptyManager: `portable-pty` crate replaces node-pty; reader thread → batched emit (tauri events or channel; use `tauri::ipc::Channel` for bytes, avoid JSON-string base64 overhead). Per-card replay ring buffer easy.
- IPC surface: ~30 handlers → `#[tauri::command]`; preload.ts replaced by `invoke`/`listen` wrapper with same `window.canvas` shape to avoid touching src/.
- Single-instance lock (`tauri-plugin-single-instance`), quit-flush handshake (`app:flush` 600ms) via window close event + emit.
Hard:
- `@xterm/headless` (read fallback, bracketed-paste mode, resize tracking) has no Rust equivalent of equal quality: use `vt100`/`alacritty_terminal` crate for screen text, or drop headless entirely (recommend: tmux capture-pane for persistent; `vt100` for non-tmux). Fixes P1 on the way.
- `capturePage` screenshot: Tauri has no cross-platform webview capture (Linux webkit2gtk: `snapshot` via gtk; limited). Hard/M-L; drop or implement via webview eval + html2canvas.
- Electron-only: `shell.openExternal` (tauri-plugin-shell/opener), `dialog.showOpenDialog` (plugin-dialog) easy. `node:sqlite` → rusqlite easy.
- WebKitGTK vs Chromium rendering of xterm.js/React Flow (perf, WebGL addon) is the real porting risk, not backend.
